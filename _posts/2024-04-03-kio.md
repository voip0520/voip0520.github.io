> **Máquina:** KIO · **Plataforma:** Hacking · **SO:** Linux RedHat · **Dificultad:** Media

## 1. Reconocimiento

El descubrimiento de hosts sitúa el objetivo en `192.168.231.133`.

![Descubrimiento de host](/assets/informes/kio/p03_01.jpg)

El escaneo de puertos con Nmap identifica varios servicios expuestos: SSH (22), HTTP (80), rpcbind (111), Samba (139), HTTPS (443) y kdm (1024).

![Escaneo de puertos](/assets/informes/kio/p03_02.jpg)

La detección de versiones revela un sistema **Linux RedHat** con versiones antiguas de Samba y Apache.

![Detección de versiones](/assets/informes/kio/p04_03.jpg)

![Servicios en ejecución](/assets/informes/kio/p04_04.jpg)

## 2. Análisis de vulnerabilidades

El análisis con OpenVAS y los scripts NSE señala software desactualizado. Entre los hallazgos destacan el protocolo SSH-1 obsoleto, métodos de depuración HTTP habilitados y, sobre todo, una versión de Samba vulnerable a **trans2open** y un Apache/OpenSSL explotable.

![Análisis de vulnerabilidades](/assets/informes/kio/p05_05.jpg)

![Resumen de hallazgos](/assets/informes/kio/p05_06.jpg)

Resumen del objetivo:

| Campo | Valor |
|---|---|
| IP | 192.168.231.133 |
| Sistema Operativo | Linux RedHat |
| Puertos | 22/SSH · 80/HTTP · 111/rpcbind · 139/Samba · 443/HTTPS · 1024/kdm |
| Vectores | Samba trans2open · Apache/OpenSSL (OpenFuck) |

## 3. Explotación

### Vía automatizada — Metasploit

Se localiza el módulo `exploit/linux/samba/trans2open` mediante `search trans2open`.

![Búsqueda del módulo trans2open](/assets/informes/kio/p06_07.jpg)

Tras revisar los parámetros con `show options` y configurar el objetivo, se lanza el ataque.

![Configuración del exploit](/assets/informes/kio/p06_08.jpg)

La explotación compromete el objetivo y otorga acceso directo como usuario administrador (root).

![Acceso como root vía Metasploit](/assets/informes/kio/p07_09.jpg)

### Vía manual 1 — exploit de Samba compilado

De forma complementaria, se emplea un exploit público en C para el mismo servicio, compilándolo:

```bash
gcc -o RunMe1 22469.c
./RunMe1 -t 192.168.231.133
```

![Compilación del exploit de Samba](/assets/informes/kio/p08_10.jpg)

![Uso del exploit compilado](/assets/informes/kio/p08_11.jpg)

La ejecución contra el objetivo proporciona nuevamente acceso como administrador.

![Acceso como root vía exploit manual](/assets/informes/kio/p09_12.jpg)

### Vía manual 2 — OpenFuck (Apache/OpenSSL)

Como segundo vector manual se clona y compila el exploit **OpenFuck**, dirigido a la versión vulnerable de Apache/OpenSSL:

```bash
git clone https://github.com/heltonWernik/OpenFuck.git
cd OpenFuck
mv OpenFuck.c OpenLuck.c
gcc -o RunMe2 OpenLuck.c -lcrypto
```

![Compilación de OpenFuck](/assets/informes/kio/p09_13.jpg)

![Preparación del ataque OpenFuck](/assets/informes/kio/p10_14.jpg)

Empleando el offset correspondiente a la versión de Apache vulnerable, el ataque se completa con éxito.

![Ejecución de OpenFuck](/assets/informes/kio/p10_15.jpg)

![Acceso obtenido](/assets/informes/kio/p11_16.jpg)

## 4. Escalada de privilegios

No se requiere escalada: las vulnerabilidades explotadas otorgan acceso directo como superusuario.

## 6. Herramientas utilizadas

Kali Linux, Nmap, OpenVAS, Metasploit Framework, GCC y exploits públicos (Samba trans2open, OpenFuck).

## 7. Recomendaciones de mitigación

Actualizar Samba, Apache y OpenSSL a versiones soportadas, deshabilitar el protocolo SSH-1, desactivar los métodos de depuración HTTP (TRACE/TRACK) y retirar el sistema operativo RedHat obsoleto del entorno productivo.
